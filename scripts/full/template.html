DESIGN & LIMITATIONS

What the percentages mean.

Experiment design

Headline metric

Journey time = actual arrival time minus the scheduled departure time. It includes waiting outside the network before admission and all time in traffic.

change = 100 × (AI average / shortest average − 1)

Negative means a reduction in average journey time. Positive means longer journeys. Shortest path is the 0% reference.

Headline and breakdown comparisons use common scenario/seed pairs in which shortest path, OpenAI and Jev all complete all requested trips. Their averages pool all trips from that same cohort. Completion outcomes for all other pairs remain visible beside the metric, and every run is present in the matrix and data exports.

No composite score is used. Percentages are displayed to two decimal places; raw values remain in the data exports. Changing the signal-policy selector changes the treatment bundle, not the reference: shortest path always uses fixed timing. This complete-system view does not isolate routing.

Run-to-completion safeguards

Arrivals stop at 1140s. The simulation keeps running while cars are inside the map or waiting to enter. It finishes only when every scheduled journey arrives.

A run stops as gridlocked if demand has ended for at least 300s and there have been no completed journeys for 300s. A 7200s total-time cap handles slow-progress or other pathological cases. A no-API probe showed a progressive extra-high baseline needed 5588.9s, so the original 3600s cap was extended uniformly and affected runs were rerun. Neither safeguard teleports vehicles or records uncompleted trips as finished.

Incomplete runs have no all-trip average or journey-time percentage. Their completed-only average, unfinished count, entry backlog and elapsed time are supplied for diagnosis.

Stability and model limits

Warm-up is 300s, changes are spaced 180s apart, and the final unrestricted recovery period has 300s of continued demand. A rolling-window stability heuristic is checked rather than assuming equilibrium.

Overloaded means the external queue grows faster than 0.05 vehicles/s across the two diagnostic windows. Steady additionally requires absolute external-queue drift ≤0.05 vehicles/s, network population drift ≤10%, and departure-rate drift ≤20% or 0.05 vehicles/s. Other windows are transient.

Two seeds are repetitions, not enough for strong significance claims. Demand is synthetic. Pedestrians, detailed turning conflicts and lane changing are not modelled. There is no congestion-aware local-only comparison arm, so a gain over shortest path cannot establish an advantage unique to an AI model. The 450-active-vehicle limit is explicit; blocked entrants wait outside and remain in every denominator.

API protocol and cost controls

Simulation time pauses at decision barriers while API calls run. Provider latency and failures are recorded separately. This measures policy outcomes, not real-time network-delay penalties.

Only identical same-provider requests may reuse an exact saved response, including shared warm-up states. Reuses are counted. Cache use is not a new independent model sample. HTTP 429 responses receive at most two paced retries; other failed requests are not automatically retried.

Data and reproduction

pnpm benchmark:full resumes complete run files and exact responses in this new study directory. It refuses to overwrite completed results. pnpm benchmark:full:report rebuilds the report with no API calls.

The initial report remains available. Its short horizon, lower demand and composite index make its numbers directly incomparable with this study's journey-time percentages.
